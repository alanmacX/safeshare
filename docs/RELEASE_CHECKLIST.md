# AppGallery release gates

任何功能只有同时通过“功能、隐私、兼容、审核材料”四个门禁后，才能在产品文案或商店素材中声明为已支持。

## 每次功能合并前

- 不记录图片 URI、文件名、二维码内容、坐标或其他敏感值。
- 输入文件只读；所有输出位于应用沙箱，并有失败、取消、分享完成和下次启动清理路径。
- 不为未来功能预申请权限。新增权限必须同步更新 `PERMISSIONS.md`，包含用途、用户可见场景、受限状态和审核说明。
- 检测结果必须来自真实 API 返回值；不把模拟数据、推断标签或尚未真机验证的能力写进产品文案。
- 失败必须可降级。例如视觉检测失败后仍可进行 metadata-only 清理，编码失败则阻止分享并删除残留输出。
- 新增格式必须通过“扫描 → 清理 → 复检”闭环，不能只因为 Share Kit 能接收就宣称支持。

## 发布构建

- 使用发布证书和发布 Profile；受限权限声明必须与 Profile 申请完全一致。
- 更新 `versionCode`、`versionName`、更新说明及隐私政策版本。
- Release 构建启用混淆，保存符号表和构建日志，并完成安装、启动、分享进出回归。
- 软件包不得包含测试照片中的真实个人数据、开发证书、调试入口、测试账号或敏感日志。
- 对第三方依赖生成许可证清单；新增依赖需记录许可证、网络行为和数据处理情况。

## 设备与体验矩阵

- 至少覆盖两台不同尺寸的 HarmonyOS 真机；模拟器结果不能代替 Share Kit、Core Vision 或 Scan Kit 真机验收。
- 覆盖浅色、深色、字体放大、横竖屏、分屏、手机和平板。
- 平板和折叠屏展开态必须支持横竖屏平滑切换；比例接近 1:1 的窗口保持一致的信息结构，不因方向名称硬切布局。
- 平板逐项验证全屏、1:2、1:1、2:1 分屏及窗口连续缩放；预览、风险列表、弹层和底部主操作不得截断、重叠、拉伸或形成无意义的大面积空白。
- 文档结果页在 `md`/`lg` 使用“文件栏 32% + 检查器 68%”主从工作台，窄窗退回单栏；应用内不模拟文档页面，真实内容统一通过系统 Preview Kit 打开，并逐一验证可用/不可用反馈。
- 覆盖 JPEG、PNG、HEIF/HEIC 的方向、透明度、超大图、损坏文件和无 metadata 文件。
- 验证图库、文件管理、浏览器分享进入；分享完成和关闭分享面板两条临时文件清理路径。
- 检查读屏标签、触控目标、对比度、动态字体裁切和加载/失败/取消状态。
- 用不同 EXIF Orientation 的横竖图逐项验证：预览框、人脸框、二维码角点和最终输出像素必须重合。
- 在 MatePad Mini 上记录单张与 10/50 张批次的首屏时间、单张耗时、峰值内存、温升和模型首次/再次调用差异；不得以提高并发换取更高内存峰值。
- 对每一种二维码/条码使用另一台设备重新扫描安全副本；模糊或马赛克仍可识别即视为失败，默认纯色覆盖必须不可识别。

## AppGallery 材料

- 隐私政策必须准确说明：无账号、无自建服务器、图片本地处理、原图只读、临时副本生命周期。
- 应用隐私说明必须与软件包实际权限一致；受限开放权限准备符合要求的使用场景视频。
- 商店截图和审核视频只展示已交付能力，并包含从系统分享面板进入、发现风险、清理、复检和继续分享的完整路径。
- 准备应用图标、手机/平板截图、功能说明、软件著作权及目标市场要求的资质材料。
- 平板商店截图必须来自实际平板布局，至少覆盖一个横屏文档结果页；不得用拉伸手机截图代替，也不得展示尚未通过真机门禁的识别能力。
